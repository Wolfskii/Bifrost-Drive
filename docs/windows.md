# Windows

Windows 11 22H2+ on NTFS is the first-release target. CFAPI lets Explorer display sync-root placeholders and hydrate files on demand. A separate WinFsp adapter provides genuine network-location or local drive-letter mounts with provider-backed filesystem operations. A connection uses its selected drive letter when configured; otherwise it uses a CFAPI sync folder, and the desktop does not register both presentations at once.

Closing the main window hides it to the persistent tray; only the tray Quit command exits Bifrost and releases mounted drives. Bifrost is single-instance, so launching it again reveals the existing tray-owned window instead of creating a competing mount owner. Drive presentation and icon choices are persisted per connection and can be changed from the full-page Edit connection view. The icon picker renders the complete Windows `SHELL32.dll` icon catalog plus named stock icons and accepts custom images or native icon sources. Network labels and icons use Explorer's MountPoints2 metadata so generated WinFsp server identities remain internal. Every normal uninstall stops the tray process, unregisters legacy CFAPI roots, and removes Bifrost DriveIcons and MountPoints2 metadata. Selecting full local-data deletion additionally removes `%USERPROFILE%\Bifrost Drive`, with locked leftovers scheduled for deletion after reboot.

Current status: Tauri desktop shell, Windows GUI-subsystem builds, per-machine Program Files installation, native start-on-boot registration, CFAPI registration, placeholder transfer, provider-backed hydration, local close/delete/rename routing, writable WinFsp callbacks, persisted drive selection, per-connection startup remount and live mount/unmount controls, provider capacity reporting where available, clean Explorer drive labels, hidden attributes for remote dotfiles, durable application history, notifications, updater configuration, and signed-package workflow support are implemented. WinFsp caches directory metadata for five seconds and grows per-handle read-ahead from 1 MiB to 16 MiB for sequential transfers; SFTP range reads use an eight-request pipeline with 2 MiB chunks over a 64 MiB SSH channel window and prefer hardware-accelerated AES-GCM when supported. The smaller delivery batches keep Explorer copy progress smooth while retaining parallel I/O. Mutations invalidate metadata immediately. Real drive acceptance covers read, write, create, rename, delete, directory operations, unmount, cache warming, and read-ahead against an in-memory provider. Explorer acceptance and throughput measurement against each live provider remain required. New SFTP connections enable trust-on-first-use by default while saved connections preserve their explicit setting. CFAPI folders are not aliased to drive letters.

Windows development requires Visual Studio Build Tools, the Windows SDK, WebView2, and a clean test account or VM. Building the native WinFsp feature additionally requires WinFsp 2.1 or later, installed from an elevated terminal with `choco install winfsp -y`. End users do not install this prerequisite separately: the Bifrost NSIS installer bundles the official unmodified WinFsp 2.1.25156 MSI, verifies its pinned checksum during packaging, and installs it silently when needed. Bifrost does not remove WinFsp during uninstall because other applications may share it. Selecting local-data deletion in the uninstaller also removes `%USERPROFILE%\Bifrost Drive`; ordinary uninstall and in-place updates preserve it.
